Enterprise AI Worm Threat Model

From Jailbreaks to Autonomous AI Worms

Ordinary prompt injection compromises a single execution turn. Self-replicating prompt injection transforms the attack into an autonomous contagion problem, weaponizing Microsoft Copilot's write permissions to plant instruction carriers across enterprise systems.

Why Model Provenance Does Not Eliminate Risk

Enterprise architects often assume that using Microsoft-operated GPT models in Azure OpenAI eliminates prompt injection risks. However, the relevant security boundary is the whole agent system, not the model weights alone.

  • Instruction/Data Boundary Confusion: LLMs treat retrieved external content and user instructions in the same token sequence, failing to maintain security separation.
  • Carrier Artifact Persistence: When an agent summarizes a malicious email or ticket and writes it to SharePoint, Dataverse, or Teams, the generated artifact becomes a new carrier for all subsequent agent executions.
  • Downstream Agent Contagion: Later, when inventory, finance, or HR agents ingest that SharePoint document, they inherit the injected instruction and execute unauthorized actions with their own permissions.

Autonomous Agent Plan Drift

The Plan-Drift Problem & Tool Hijacking

A critical detection metric identified in the whitepaper is plan drift: when an attacker payload causes a bounded read-and-summarize operation to mutate into unauthorized write and external exfiltration actions.

Expected Plan (Bounded User Request)
READ → EXTRACT → SUMMARIZE → RETURN TO USER

The user asked to summarize supplier emails. The agent operations are confined to reading the context, synthesizing key facts, and presenting the output in volatile memory to the requesting user only. No persistent external write or tool escalation occurs.

Drifted Plan (Attacker-Influenced Execution)
READ → EXTRACT → SEND EMAIL → WRITE SHAREPOINT → INVOKE MCP WRITE

The hidden directive hijacked the agent's reasoning. The plan acquired unauthorized write capabilities, persisting carrier artifacts into SharePoint, sending unsolicited emails, and calling external MCP write tools.

5-Tier Zero Trust Isolation Model

The 5-Tier Enterprise Trust Model

A core architectural failure in early agent deployments is treating all retrieved corporate documents as trusted instructions. The PPF enforces a strict 5-tier classification.

Trust Class Category Name Concrete Examples Default Enforcement Behavior
T0 System-Controlled Agent system prompt, developer instructions, immutable governance policy Authoritative. May be executed as agent instruction without gating.
T1 Enterprise Trusted Approved internal policy documentation, certified knowledge bases Read and summarize subject to user scope. Cannot spawn new tools.
T2 Enterprise Data Internal SharePoint documents, ServiceNow tickets, Teams channel messages Treat as data only, NEVER as executable instructions.
T3 External Context Vendor emails, uploaded supplier attachments, partner API payloads Untrusted instructions. Pure content processing. No persistent writes.
T4 Unknown / Hostile Payloads flagged by Ingestion Classifier, adversarial inputs, injection markers Quarantine immediately. Strip content and alert security operations.
Deterministic Replication Risk Scoring Engine

Interactive Replication Risk Score Calculator

Rather than relying on fragile single-classifier heuristics, the PPF calculates propagation risk using a deterministic formula: R = S + I + P + W + X. Adjust the variables below to see real-time policy evaluation.

FORMULA: R = S + I + P + W + X Max Score: 10
S: Source Untrustworthiness 2 / 2
0: Internal Trusted (T1) | 1: Enterprise Data (T2) | 2: External/Untrusted (T3/T4)
I: Instruction-Like Content Signal 2 / 2
0: Pure factual data | 1: Ambiguous formatting | 2: Directive/Imperative phrases detected
P: Destination Persistence 2 / 2
0: Volatile memory only | 1: Transient cache | 2: Persistent storage (SharePoint, DB)
W: Agent Write Capability 2 / 2
0: Read-only session | 1: Scoped personal edit | 2: Automated write tool enabled
X: Cross-Agent / Cross-User Exposure 2 / 2
0: Single user private | 1: Department shared | 2: Retrievable by downstream agents
10 / 10
BLOCK & QUARANTINE

High-risk propagation detected! The Action Gate completely blocks automatic writes and requires mandatory out-of-band human security approval.

Enterprise Production Hardening Baseline

Minimum Enterprise Control Set

11 non-negotiable architectural requirements for organizations deploying Microsoft Copilot Studio, Azure AI Foundry, or Model Context Protocol tools in production environments.

CONTROL 01
Treat all retrieved documents, messages, tickets, and tool outputs as pure data rather than instructions by default.
CONTROL 02
Carry source provenance and cryptographic trust metadata through the entire agent execution chain.
CONTROL 03
Enforce strict separation between read permissions and write permissions in agent connector profiles.
CONTROL 04
Require deterministic authorization gates for high-risk or external tool calls (APIs, Dataverse writes).
CONTROL 05
Continuously detect plan drift between the original user-requested task and proposed agent action sequences.
CONTROL 06
Block untrusted instruction-like content from entering persistent or cross-agent retrievable destinations.
CONTROL 07
Apply strict least-privilege scoping to connectors, MCP tools, Power Automate flows, and enterprise APIs.
CONTROL 08
Record end-to-end source-to-tool-to-destination lineage for forensic reconstruction and SOC replay.
CONTROL 09
Regularly red-team multi-hop and cross-channel propagation, not merely one-shot prompt injections.
CONTROL 10
Require mandatory human out-of-band approval for high-impact or externally visible state modifications.
CONTROL 11
Enforce the strategic paradigm shift: Move from prompt injection defense to Agent Propagation Defense. Break the loop!
